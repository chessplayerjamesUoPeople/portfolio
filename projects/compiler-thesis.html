Cóndor Compiler

An original programming language with Spanish keywords and built-in sound and graphics, plus the compiler and editor to go with it, built to make a first programming course easier for high-school students in Ecuador.

Overview

Why a new language?

Programming courses at my university's engineering faculty had high failure and repeat rates, and many students dropped out of the computer systems and software engineering programs, even those who arrived with a technical high-school diploma in computing. The programs also had far fewer women than men.

Almost every mainstream language uses English keywords, which adds a language barrier on top of the logic for students who don't speak English. Cóndor removes that barrier. Its keywords are in Spanish, identifiers can use accented letters and ñ, and programs can play sounds and draw graphics to keep beginners interested, which research suggests also helps close the gender gap.

The thesis is titled Desarrollo de un compilador de un lenguaje de programación original para facilitar el proceso de aprendizaje de programación en estudiantes de bachillerato and was supervised by MSc. Fernando Garrido.

The language

Familiar structure, native words

Cóndor follows C#-style structure so students can move on to a mainstream language later. Source files use the .sms (Spanish Multimedia Source) extension.

Multimedia built in

  • Sound: reproducir plays a .wav file and sonido plays a tone at any frequency and duration.
  • Graphics: a dibujar block opens an XNA window, with textura and color types and dibujarras to draw images.
  • Everyday helpers: console input and output, math functions, random numbers, file reading and writing, and type conversion.
  • Deliberately small: lambda and bitwise operators were left out to keep it introductory.

The compiler

A single-pass compiler, built by hand in C#

The parser drives the whole pipeline: it pulls tokens from the lexer and calls semantic routines as each grammar rule is recognized, so errors are found quickly in one pass.

  1. 1LexerTable-driven finite automaton returns tokens on demand
  2. 2LALR(1) parserBottom-up parser over 107 grammar rules
  3. 3Semantic analysisType checks and the symbol table, emitting C# as it goes
  4. 4C# compileWrites a .cs file and invokes Microsoft's C# compiler
  5. 5RunThe new .exe launches immediately

A lexer shrunk by 85%

The first deterministic finite automaton had 36 states and 104 inputs, or 3,744 table cells. Treating keywords as identifiers (looked up afterward), grouping character classes, and removing dead-end states brought it down to 16 states and 544 cells, under 15% of the original size.

An LALR(1) parser

I chose LALR(1) for its broad language coverage, speed, and early error detection. The parse table has 234 states, 55 terminals, and 40 non-terminals, and is loaded from data files rather than hard-coded.

Errors that don't stop you

The lexer skips unrecognized characters and keeps going. The parser uses phrase-level recovery: when a fix is obvious, such as a missing colon, it inserts the token, reports the error, and keeps parsing. Only serious errors stop the analysis.

Translation by synthesized attributes

Each grammar rule has a syntax-directed definition that builds C# code bottom-up on a stack, simulating the parse tree without building one. Risky statements are wrapped in try/catch so a runtime error doesn't end the program, and the code is recompiled without the wrapper if that fails.

Code followed MISRA-C reliability guidelines adapted to C#: no goto, no recursion, braces on every block, a break in every switch case, and background threads for updates and telemetry.

The editor

An IDE made for beginners

  • Syntax highlighting by token type, with unrecognized text underlined in red.
  • Live error checking three seconds after you stop typing, with an error table showing the line, error type (lexical, syntactic, or semantic), and description.
  • Keyword autocomplete and right-click templates for every loop and control structure.
  • A trace mode that records each variable's values during a run, like a desk check.
  • Built-in manuals, worked exercises, and example programs students can remix.
  • Silent auto-updates: the app checks an XML version manifest, downloads the new build, verifies its MD5 hash, and restarts.
  • Compile telemetry (source code and errors) sent to an Azure SQL database, which later powered the evaluation.

Results

Evaluated against ISO/IEC 25010

I measured performance efficiency and functional suitability, logged real student compilations, and surveyed 40 users. Most were high-school computing students, and 45% had never programmed before.

92.5% Would recommend it to beginners 40 survey respondents
95% Say multimedia boosts interest No negative answers on enjoying the multimedia features
93% Found the syntax easier Compared with other languages, among experienced programmers
3,854 Real compilations logged From 42 users; 54% had zero errors and 86% had at most one
< 1 s Compile and launch 904 ms on a modern PC, 1.6 s on a dual-core Pentium
53 MB Peak memory 29 MB on average, so it runs on low-end lab computers

What the data showed

  • 82.5% said Cóndor could be used as a first programming language in schools, and 80.6% of first-time programmers said it would encourage them to keep studying programming.
  • About 90% of logged errors were syntactic, which points to better error messages as the biggest opportunity.
  • Overall scores: 79.8% functional completeness, 88.3% functional correctness, and 84.8% functional appropriateness.

What I'd do next

  • Run a controlled study comparing a class taught in Cóndor with one taught in Python, C#, or Java.
  • Open-source it so others can translate the keywords into more languages; the compiler needs few changes to support another language.
  • Port it to a cross-platform runtime so schools can use free operating systems such as Linux.
